# Внедрение — запуск клиента

Практическое руководство по запуску клиники на Zabota 2.0, собранное из статей
пространства «Внедрение» корпоративной базы знаний Teamly (42 файла,
зеркало — [`teamly/Внедрение/`](teamly/Внедрение/)).

Документ описывает процесс «как есть» по регламентам отдела внедрения: от приёма
сделки из отдела продаж до передачи клиники медицинскому маркетологу и в поддержку.
Всё, что ниже, — факты из статей; там, где в статьях пробел, это отмечено явно
(«в статьях не описано»).

Оговорка по полноте источника: 11 из 42 статей — заглушки (пустой текст, вложение,
видео или ссылка на диск). Они перечислены в разделе «Источники» и не дают
содержательных фактов: `Внедрение`, `Регламенты отдела внедрения`,
`Брифы и данные для интеграции`, `Совместные регламенты…`, `Самостоятельная
интеграция с МИС`, `Запрос данных для интеграции`, `Воронка отправки сообщений…`,
`Бот`, `Правка сценариев для ТГ/Вайбер`, `Эффективность сценариев в брифе`,
`Модуль ответов. Обучение для администраторов`.

### Критерии приёма клиники на внедрение

Клинику можно принимать, только если выполнены все условия
([зоны ответственности](teamly/Внедрение/Зоны ответственности отдела продаж и отдела внедрения во время этапа внедрения [21d7aeea].md)):

- клиника понимает, что купила (пакет тарифа и его наполнение);
- клиника готова предоставить доступы;
- у клиники есть МИС и они в ней работают;
- ПК подходит под минимальные требования для установки Zabota Desktop **или** клиника готова использовать облачную версию;
- у клиники есть лицензия на осуществление медицинской деятельности.

### Разграничение с отделом продаж

КВ ведёт все вопросы по процессу внедрения, доносит ценность продукта, информирует
о проделанной работе и отвечает за исправность работы продукта. ОП подключается, если:

- клиника передана на внедрение и не выходит на связь (на любом этапе);
- клиника отказывается предоставлять доступы;
- у клиники вопросы по тарифу и его наполнению, обещаниям менеджера, скидкам и снижению АП;
- клиника требует связь с менеджером ОП;
- у клиники нет понимания, что куплен пакет тарифа, или непонимание ценности продукта.

По запросу ОП куратор приходит на заранее согласованную встречу и отвечает на вопросы
клиники; МП передаёт портрет клиники и список вопросов.

### Сроки и контроль

- Сделка двигается по этапам своевременно; переводить сделку на предыдущий этап **нельзя**.
- Еженедельно заполняется «Процент выполнения внедрения» (задача приходит автоматически) и «Текущие работы».
- Перед планеркой по вторникам — комментарий в сделке о текущем состоянии клиники.
- Ответ коллегам из других отделов — не более 30 минут; на время встреч ставится статус «Не беспокоить».
- Время по клинике фиксируется в 4 задачах: «Общение», «Битрикс», «Бриф», «Акция».

Отдельный регламент — [фиксация времени работы с клиниками](teamly/Внедрение/Фиксация времени работы с клиниками [50f0edcd].md):
типы задач для трекинга — Аккаунтинг, Акция, Воронка, Встреча/Чат, Кейс,
Настройка/Правки сценария, Отчет, Работа с брифом, Прочее; общие — Внутренние задачи,
Вн. встреча/Обучение, Короткие задачи, Чаты.

## Подключение МИС и интеграций

### Поддерживаемые МИС

Прямо в статьях пространства названы:

| МИС / система | Что известно из статей |
|---|---|
| IDENT | Полная пошаговая инструкция установки, отдельный регламент проверки после установки. Основной описанный сценарий |
| Инфодент | Отдельная статья-папка с материалами (ссылка на Google Drive); заявка на обмен через портал ИНФОКЛИНИКА |
| Инфоклиника | Обмен через портал ИНФОКЛИНИКА.RU, заявка с подписью и печатью |
| 1С (БИТ, Хеликс, Stoma1c) | Чек-лист по интеграции 1С: берём файловую/серверную БИТ, Хеликс, Стоматологическую клинику (stoma1c.ru) |
| 1С:Медицина, 1С:Больница, 1С:Поликлиника | «Не берём, не делаем» |

В форме создания установщика МИС выбирается из списка; «если МИС нет в списке —
поле пропускаем». Полный перечень поддерживаемых МИС в статьях отсутствует —
см. карту продукта и `architecture.md`/`import.md`.

### Что нужно от клиники

- **Доступ к БД МИС.** Без него интеграция невозможна (прямая формулировка чек-листа 1С).
- **Параметры подключения.** Для IDENT: адрес БД (имя компьютера или IP), при IP — маска `IP,15000`;
  поля «Инстанс», «База данных», «Пользователь» — по умолчанию; **пароль клиника запрашивает
  у техподдержки МИС IDENT**. Если данных нет, но IDENT стоит на машине — берём `DB.config`
  рядом с ярлыком и копируем значение из строки `<Host>`.
- **Справочники и выгрузки** по таблицам из [«Таблицы, которые Zabota 2.0 выгружает из МИС»](teamly/Внедрение/Таблицы которые Zabota 2.0 Выгружает из МИС. [742d33dd].md):
  Patients, Patients_statuses, Doctors, Visits, Status_types, VisitsStatuses, Procedures,
  Treatments, Diagnosis, Patients_diags, Patients_queue, Queue_types, Departments,
  predpat (необязательная).
- **Данные для интеграции** — по анкете/письму (см. «Шаблоны и артефакты»).
- **Технические условия:** ОС Windows Server / Windows Pro (Windows Home не подходит),
  ветка установщика beta, отключённый антивирус на время установки и исключение для папки `Zabota 2.0`.

### Порядок подключения IDENT (сжато)

1. Подключиться к клинике, скачать установщик (ветка **beta**), отключить антивирус, добавить исключение.
2. Запустить от имени администратора.
3. Пройти мастер: проверка связи с серверами Zabota (при ошибке установка не продолжится),
   режим установки, папка, компоненты (все галочки, «Установить интеграцию» → Ident).
4. Проверить соединение с БД МИС, выбрать филиалы, нажать «Заполнить базовыми параметрами».
5. Настройка БД — оставить по умолчанию, **пароль скопировать и сохранить**.
6. Подтвердить установку. При ошибках — задача в отдел техподдержки с описанием и скриншотами.

### Проверка после установки (IDENT)

Остановить службы `cr2importer*` и `cr2producer*` (Диспетчер задач → Службы; на Windows 7 —
оснастка «Службы»), запустить `server\In\ZabotaMisExporter`, затем смотреть логи в
`server\In\Logs` (файлы по датам). Типовая правка: в `server\In\scripts\patients.ns`
заменить `pat.email` на `p.email`.

### Особенности 1С

| Вопрос | Вариант | Решение по чек-листу |
|---|---|---|
| Доступ к БД | Да / Нет | Да — берём; Нет — интеграция невозможна |
| Подключение к БД | Файловая / Серверная / Облачная | Файловая и серверная — берём; облачная — сложно, смотреть отдельно |
| Облако | fresh1c.ru, enot.ru, stoma1c.ru | Интеграция невозможна |
| Облако | Scloud.ru, rarus/rent1c | Сложно (rent1c — теоретически возможна, не отлажена) |
| Облако | Собственное / аутсорсера 1С клиники | Изучать; технически просто, но много согласований доступов |
| ОС | Windows Home | Не подходит |
| ОС | Linux | Не ставили, возможно в порядке эксперимента |
| ОС | Windows Server, Windows Pro | Берём |
| Конфигурация | БИТ, Хеликс, Стоматологическая клиника (stoma1c.ru) | Берём |
| Конфигурация | 1С:Медицина, 1С:Больница, 1С:Поликлиника | Не берём, не делаем |
| Конфигурация | 7.7, старая 1С, своя/переписанная программа | Сложно, изучать |

Резюме чек-листа: «самый 100 % вариант» — файловая или серверная БИТ, Хеликс, Stoma1c.
Клиника часто сама не знает, в каком облаке работает, — нужно запрашивать их программиста;
как альтернативу можно предложить покупку коробочной версии.

### ИНФОКЛИНИКА (Инфодент, обмен с внешней системой)

Для перевода клиники в статус подключённой формируется заявка по форме (внешняя система,
клиника, число филиалов, наличие техподключения к порталу, контактные лица с обеих сторон),
заверяется подписями и печатями Заботы и клиники, скан отправляется через
`https://support.sdsys.ru/`. Данные со стороны Заботы: Zabota 2.0, оператор — ООО «Медицина»,
аттестата по уровню защищённости нет, размещение — оборудование клиники,
ТП +7 (499) 322-21-85, 10:00–19:00, support@zabota.tech.

### Типовые проблемы при подключении

- Нет доступа к БД МИС или клиника отказывается его давать — интеграция не начинается.
- Пароль БД не у клиники, а у техподдержки МИС — запрос идёт через клинику, это закладывается в срок.
- Windows Home на машине выгрузки — не подходит, нужна замена ОС или другой ПК.
- Облако 1С (fresh1c, enot, stoma1c) — интеграция невозможна, вопрос решается на пресейле.
- Ошибка выгрузки IDENT из-за `pat.email` в `patients.ns` — правится по регламенту проверки.
- Антивирус блокирует установку/работу — исключение для папки `Zabota 2.0`.
- Ошибки установки — передача в ТП (в статье по установщику указаны Андрей Красовский,
  Дмитрий Серов, Алексей Трефилов).

## Настройка каналов

### WhatsApp / WABA

- Привязка WhatsApp — задача 1-й линии ТП через «умные сценарии» на этапе «Подготовка к запуску».
- Запуск делать с учётом количества отправленных сообщений, чтобы **избежать блокировки WhatsApp**
  (требование чек-листа перед запуском).
- Личный кабинет Wazzup: видео по добавлению номера, добавлению шаблона и чатам с клиентами
  (≈30 мин) — в [ссылках на обучающие материалы](teamly/Внедрение/Ссылки на обучающие материалы [04f69395].md).
- Риск: мессенджер уже отключался, возможна полная блокировка — отсюда диверсификация каналов.
- Что нужно от клиники: номер, доступ в ЛК Wazzup, шаблоны сообщений на согласование.

### Telegram

Подключение **по желанию клиники**, цель — диверсификация каналов: если WhatsApp заблокируют,
часть сообщений уйдёт через бота ([инструкция](teamly/Внедрение/Инструкция по подключению Telegram бота на этапе Внедрения [ea8c5ace].md)).

Что делает клиника:

1. Создаёт бота у `@BotFather` (`/newbot`), получает имя, никнейм (обязательно на `bot`) и **токен**;
   токен передаёт куратору.
2. Регистрирует личный кабинет на `https://lkbot.zabota.tech/reg_mini/`.
3. Создаёт публичный или частный канал для заявок на запись; ссылка должна быть сложной,
   в открытый канал может зайти любой; ссылку передаёт куратору.
4. Добавляет в канал `@zabotaheadoperatorbot` с правами администратора.
5. Узнаёт ID канала через `@getmyid_bot` / `@username_to_id_bot`: пересылает публикацию
   из канала, в ответе «Forwarded from chat» — нужный ID (с минусом).

Что делаем мы: после регистрации бота ставим задачу на Дмитрия Кулешова в Битрикс24
для подключения бота на нашей стороне; правим сценарии под ТГ-бота и делаем тестовые отправки
(видео — [Правка сценариев для ТГ-бота…](teamly/Внедрение/Правка сценариев для ТГ-бота и Вайбер-бота, тестовые отправки в ТГ-бот [297360d4].md)).

Почему Telegram: бизнес-процессы и чаты связаны с внутренней системой, бот мониторит чаты,
сохраняется история при смене сотрудников, можно закреплять важные сообщения,
в Telegram приходят автоуведомления об отвале привязки WhatsApp
([Почему мы используем телеграм](teamly/Внедрение/Почему мы используем телеграмм [5aa6efb3].md)).

### Viber

**Подключение временно приостановлено** из-за изменения политики Viber. Инструкция сохранена
(создание бота на partners.viber.com, картинка 400×400, URI, категория, токен, QR-код).

### SMS (Интис)

- В поле «Интис» в сделке фиксируется, будет ли клиника использовать досыл SMS.
- При «Да» до запуска заполняются логин и пароль от ЛК Интис.
- Регистрация ЛК — по реферальной ссылке `https://new.sms16.ru/register/?ref=…`, данные вносятся в сделку.
- Регистрация имени отправителя — платная у всех операторов; при желании клинику отправляют в Интис;
  иногда нужен договор аренды домена (задача на внутреннего аккаунта).
- Проблемы с дублями кабинетов — письмо Венере (venera@intistele.com).

### Email

В статьях пространства «Внедрение» настройка e-mail-канала **не описана** (ни требования
к домену, ни SPF/DKIM, ни поставщик). Пробел источника.

### Звонобот

В статьях пространства «Внедрение» звонобот **не упоминается**. Пробел источника;

### Что показываем персоналу клиники

- **Модуль ответов** — обязательное обучение администраторов (отдельный файл-материал и запись
  внутреннего обучения). Обучение модулю ответов — пункт чек-листа передачи клиники в поддержку.
- **Работа в системе** — по инструкции для управляющего контакт-центра/администратора и памятке пользователю.
- **Тестовые отправки** — на них обращаем внимание клиники на работу с отзывами по NPS и анкетированию.
- **Ценность для администраторов**: экономия времени за счёт автоматизации обзвона по приёмам,
  предложениям и сбору обратной связи (квизы, лендинги).
- **Сертификат администратора**: в сделке → «Документ» → шаблон «Сертификат для админов клиники»,
  вписать полное ФИО и дату выдачи (дата обучения или текущая), имя документа — фамилия и инициалы,
  сохранить, скачать PDF и отправить клинике
  ([инструкция](teamly/Внедрение/Как создать сертификат для администратора клиники [ac1235e8].md)).

### Передача клиники в поддержку

Передаёт куратор внедрения медмаркетологу. До входа маркетолога в чат должно быть сделано:

- проставлена глубина: базовый пакет сценариев запущен не менее 40 % (Профессиональный,
  Многопрофиль) или 60 % (Оптимальный, Стартовый, Лайт, Смарт, Сервис+); меньше — решает
  комиссия руководителей внедрения и маркетинга;
- оплачена первая абонплата (подтверждение бухгалтерии или платёжное поручение);
- проведено обучение модулю ответов;
- подписано согласие о запуске.

Рекомендованный блок сценариев: информационный блок, напоминания о приёме, блок обратной связи,
маркетинговый блок (зубная формула, если есть в МИС). На каждый филиал — отдельный сценарий
с указанием филиала.

Далее в течение 3 дней маркетолог проверяет: соответствие сценариев в PR2 и брифе; документы
в Битриксе (договор, согласие о запуске, допсоглашение о переходе на облако — опционально);
бриф в папке клиники и ссылку на него в сделке; видеовстречи на диске Битрикс; поля сделки
(название в формате «ID номер Название клиники Юрлицо», ЛПР и контакты, блок информации
для интеграции, закреплённый комментарий с особенностями клиники); лендинги на `s.z20.pw`
(конструктор Mobirise); ТЗ на нестандартные квизы в папке клиники.

Сроки по регламенту: назначение маркетолога — 1 сутки; проверка — 2 суток (не успел —
клиника считается принятой); донаходка несоответствий — ещё 3 суток, задача куратору на 3 дня;
правки куратора — 3 суток. Представление маркетолога в чате идёт по готовому тексту,
маркетолог добавляет клинику в сводную таблицу `http://z20.su/CAV` и заполняет блок медмаркетинга
и соцсетей в сделке.

### Передача куратор-куратор и паузы

- Передавать клинику между кураторами можно только в случаях: отпуск, длительная болезнь,
  увольнение, просьба клиники после согласования с руководителем. До передачи — заполнить в сделке:
  что сделано, что сделать в отсутствие, главное контактное лицо, особенности внедрения;
  закрыть ответами все задачи; добавить замещающего в чат и представить его клинике.
- «Потеряшка» — нет связи более 2 недель. До передачи: ≥2 звонков в неделю по всем номерам,
  ≥2 сообщений в неделю в чат, попытки найти дополнительных контактных лиц через менеджера ОП.
  Далее чат с руководителем внедрения и менеджером ОП, план поиска; если за 2 недели не нашли —
  воронка «Отток».
- Долгая пауза: уведомить ОП и руководителя, комментарий в сделке с причиной и сроками,
  созвон об условиях остановки (особенно при рассрочке), перенос в «Отток» на этап
  «Пауза на внедрении».
- Если клиника пропала до первой встречи — возврат в отдел продаж с комментарием и задачей менеджеру ОП.
- Согласование брифа дольше 3 недель или любая другая пауза — подписывается дополнительное
  соглашение о продлении сроков (задача внутреннему аккаунт-менеджеру со сроком рабочий день;
  указать дату приостановки и причину; подписанный допник — в сделку).

### Окончание внедрения (документы, с 01.04.2024)

Менеджер ОП отправляет договор и два счёта; передаёт клинику на внедрение после оплаты счёта
за внедрение. Крайний срок оплаты первого месяца АП — 1-е число месяца, следующего за месяцем
запуска. На этапе «Подписание акта за внедрение» создаётся автозадача бухгалтеру.
Без ЭДО: скан акта в чат + два оригинала акта и два экземпляра договора на адрес Заботы
с трек-номером; после этого внедрение считается завершённым. Передача на поддержку — после
подтверждения подписания акта и оплаты АП; при отсутствии оплаты систему отключают в первый
рабочий день следующего месяца.

### Довнедрение и перевнедрение

Повышение тарифа, смена МИС, переустановка Windows — повод для бизнес-процесса
«Процесс повторное внедрение»: медмаркетолог сообщает в ОП для расчёта и счёта (либо работы
в рамках АП), после оплаты запускает БП в сделке, тот повторяет все этапы внедрения,
руководитель внедрения назначает куратора. Отслеживание — CRM → Смарт-процессы →
Смарт-процесс «Внедрение». После оплаты новой АП БП завершается, клиент возвращается
медмаркетологу в воронку «Поддержка».

## Типовые ошибки внедрения

| Симптом | Причина | Как избежать |
|---|---|---|
| Первичность в выгрузках определена неверно | Не проверена логика первого визита в МИС | Проверять первичность в выгрузках до запуска (чек-лист) |
| Клиника говорит, что выгрузка неверна, уже после запуска | Выгрузки не согласованы с клиникой | Согласовывать выгрузки по каждому запускаемому сценарию письменно |
| Пациенты других филиалов не учитываются или дублируются | Не настроена ЦБД и визиты в другие филиалы | Учитывать визиты в другие филиалы, если не требуется иное |
| Рассылка ушла в нерабочий день / в нерабочее время | Сценарии не учитывают нерабочие дни и расписание | Проверять расписание: даты запуска и время работы во всех сценариях |
| Клиника недовольна текстом сообщения | Тексты не согласованы | Согласовывать все тексты до запуска |
| Ссылка в памятке ведёт не туда | Не проверены скрытые ссылки (в т.ч. в логотипе) | Проверять все ссылки, включая скрытые |
| Нет юридической защиты при претензии по запуску | Не подписано согласие на запуск | Подписать и загрузить согласие в сделку до запуска |
| WhatsApp заблокировали на старте | Массовая отправка без учёта лимитов | Запускать с учётом количества сообщений; диверсифицировать каналы (Telegram/Viber) |
| Бриф не совпадает с настройками в PR2 | Бриф вели отдельно от системы | Бриф и PR2 должны быть идентичны; сверить коды, ФИО врачей, тексты, квизы, фильтры |
| Отчёты в репортере не строятся | Названия сценариев не стандартизированы | Называть сценарии строго по шаблону (см. ниже) и проставлять тип сценария |
| Ошибка выгрузки IDENT | В скрипте `patients.ns` поле `pat.email` | Заменить на `p.email` по регламенту проверки |
| Интеграция 1С не встала | Облако fresh1c/enot/stoma1c, 1С:Медицина, Windows Home | Проходить чек-лист 1С **до** обещаний клиенту |
| Установка падает / работает нестабильно | Антивирус, ОС ниже требований | Исключение для папки `Zabota 2.0`, проверка требований ПК/Cloud |
| Клиника пропала на 2+ недели | Нет системы напоминаний и фиксации попыток связи | ≥2 звонков и ≥2 сообщений в неделю, поиск доп. контактов через ОП |
| Внедрение «зависло» на согласовании брифа | Бриф согласуется дольше 3 недель | Подписывать допсоглашение о продлении сроков, указывать дату приостановки |
| Сделка стоит на месте, причины не ясны | Не заполняется процент внедрения и комментарии | Еженедельно заполнять процент и «Текущие работы», комментарий перед планеркой |
| Клинику не принял маркетолог | Не закрыт чек-лист передачи (глубина, АП, обучение, согласие) | Прогонять чек-лист передачи до перевода сделки |
| Клиника отключена в начале месяца | Не оплачена АП | Комментарий в сделке (с какого числа и на какую почту АП), контроль получения и оплаты |

Стандартизация названий ([шаблоны](teamly/Внедрение/Стандартизация наименований сценариев [ac788d07].md)):
«Сообщение о записи [возраст] [первичность]», «Напоминание о приеме за [N дней] [возраст] [первичность]»,
«Анкетирование [возраст]», «NPS [возраст]», «Приглашение на [услуга] [возраст]»,
«Поздравление с [событие] [возраст] [есть ли запись]», «ПБС [название]», «Акция [дата запуска] [название]».
