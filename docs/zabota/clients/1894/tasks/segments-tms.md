## 3. Чего в выгрузках нет (без этого сегмент не «залить»)

1. **`deliveries`** — есть ли уже эти сценарии, их `delivery_id`, `code`,
   `dname`, активность, каналы (WA/TG/MAX). Без этого непонятно, писать новые
   сегменты или править существующие, и какой `:DID` подставлять.
2. **`deliv_conditions`** — текущие сегменты этой клиники: их стиль (ручной SQL
   или конструктор, `saved_code`), используемая обёртка/вьюхи. Заодно проверка,
   что `vpatients`/`patients_visits` в этой базе устроены так же.
3. **`deliv_params`** — есть ли привязки `:IPAT`, `:ITIME1/2`, `:DID`; используются
   ли группы процедур (`:IGROUP`/`:GROUPID`). По брифу групп нет — услуги
   перечисляются списком, но подтвердить по базе.
4. **`delivery_schedule_trigger`** — «1 сообщение каждые 17 минут» и окно
   09:00–19:00 задаются там, а не в SQL (в сегменте только страховка
   `datepart(HOUR, GETDATE()) BETWEEN :ITIME1 AND :ITIME2`).
5. **Значения `Visit_state`** в этой базе (в `wellness_new` `N` — активный,
   `C` — отменён; предполагаю то же, но это надо увидеть в их выгрузке).
6. Решения по логике, которых нет в брифе:
   - сценарий 2: нужен ли «нет записи на будущее» (в брифе его нет) и
     антиповтор (не чаще раза в N дней) — иначе «регулярный» сценарий будет
     долбить одного пациента;
   - «нет записи на будущее» — к любым врачам или только к списку, и на какой
     горизонт (стандарт 60 дней);
   - приём у психиатра/психотерапевта считать по `patients_visits` (визит) или
     по `patients_treatment` (услуга) — в брифе «приём», но в базах бывает и так,
     и так;
   - для детей: список врачей тот же (22) или нужен отдельный «детский» список —
     в `doctors` нет ни специальности, ни признака «детский врач».

## 4. Черновики сегментов (после подтверждения п. 2–3)

**Готовые к вставке сегменты — в `segments-tms.sql`** (это источник истины,
все три прошли `SET PARSEONLY ON`). Ниже — те же тексты для чтения.

Параметры: `:IPAT` (1 для «каждые 17 минут»), `:ITIME1`/`:ITIME2` = 9/19,
`:DID` — подставляет PR2 при запуске, в тексте оставляем как есть.

### 4.1 ТМС для взрослых (разовая)

```sql
SELECT TOP (:IPAT) vv.* FROM (SELECT patients.* FROM vpatients patients
WHERE
    cellphone LIKE '79%'
    AND hide = 0 AND Exclude = 0
    AND age >= 18                                  /* возраст от 18 лет */

    /* было 2 и более приёма у психиатра/психотерапевта:
       визит ИЛИ оказанная услуга, даты не задваиваются (UNION) */
    AND 2 <= (
        SELECT COUNT(*) FROM (
            SELECT pv.Patient_Id, CONVERT(date, pv.Visit_date) AS d
            FROM patients_visits pv
            WHERE pv.visit_state <> 'C'
              AND pv.doctor_id IN (48,160,190,221,238,282,297,301,302,334,339,
                                   348,351,384,385,393,394,408,412,416)
            UNION
            SELECT pt.Patient_id, CONVERT(date, pt.Treatment_date)
            FROM patients_treatment pt
            WHERE pt.doctor_id IN (48,160,190,221,238,282,297,301,302,334,339,
                                   348,351,384,385,393,394,408,412,416)
        ) exams
        WHERE exams.Patient_Id = patients.patient_id
    )

    /* была получена услуга ТМС 90-720 дней назад */
    AND EXISTS (SELECT 1 FROM patients_treatment pt
         WHERE pt.Patient_id = patients.patient_id
           AND pt.Procedure_id IN (1477, 21475, 23524)   /* ТМС */
           AND DATEDIFF(DAY, pt.Treatment_date, GETDATE()) BETWEEN 90 AND 720)

    /* нет записи на будущее */
    AND NOT EXISTS (SELECT 1 FROM patients_visits pv
         WHERE pv.Patient_Id = patients.patient_id
           AND pv.visit_state <> 'C'
           AND DATEDIFF(DAY, GETDATE(), pv.Visit_date) BETWEEN 0 AND 60)

    /* разовая отправка: этому номеру по этому сценарию уже не слали */
    AND NOT EXISTS (SELECT 1 FROM messages m
         INNER JOIN deliv_orders do ON do.Order_id = m.Order_id
         WHERE do.Delivery_id = :DID
           AND m.Contact_info = patients.cellphone)
) vv
LEFT JOIN (
    SELECT v1.patient_id FROM patients v1
    INNER JOIN patients v2 ON v2.cellphone = v1.cellphone
    WHERE v1.patient_id > v2.patient_id
) duplicatePatients ON vv.patient_id = duplicatePatients.patient_id
WHERE
    duplicatePatients.patient_id IS NULL
    AND datepart(HOUR, GETDATE()) BETWEEN :ITIME1 AND :ITIME2
```

### 4.2 ТМС для взрослых (регулярный)

Блок «2 и более приёма» заменяется на (визит ИЛИ услуга 7 дней назад):

```sql
    /* приём у психиатра/психотерапевта 7 дней назад: визит ИЛИ услуга */
    AND (
        EXISTS (SELECT 1 FROM patients_visits pv
            WHERE pv.Patient_Id = patients.patient_id
              AND pv.visit_state <> 'C'
              AND DATEDIFF(DAY, pv.Visit_date, GETDATE()) = 7
              AND pv.doctor_id IN (48,160,190,221,238,282,297,301,302,334,339,
                                   348,351,384,385,393,394,408,412,416))
        OR
        EXISTS (SELECT 1 FROM patients_treatment pt
            WHERE pt.Patient_id = patients.patient_id
              AND DATEDIFF(DAY, pt.Treatment_date, GETDATE()) = 7
              AND pt.doctor_id IN (48,160,190,221,238,282,297,301,302,334,339,
                                   348,351,384,385,393,394,408,412,416))
    )
```

остальное (возраст, ТМС 90–720, телефон, дедуп, часы) — как в 4.1.
Если «нет записи на будущее» нужно и здесь — добавить тот же `NOT EXISTS`.
Антиповтор: `AND NOT EXISTS (... messages ... Delivery_id = :DID ... )`.

### 4.3 ДЕТИ 3–17, анонс курса

```sql
SELECT TOP (:IPAT) vv.* FROM (SELECT patients.* FROM vpatients patients
WHERE
    cellphone LIKE '79%'
    AND hide = 0 AND Exclude = 0
    AND age BETWEEN 3 AND 17                        /* 3-17 лет включительно */

    AND (
        /* были визиты у детского психиатра/психотерапевта/психолога за 24 мес */
        EXISTS (SELECT 1 FROM patients_visits pv
            WHERE pv.Patient_Id = patients.patient_id
              AND pv.visit_state <> 'C'
              AND DATEDIFF(DAY, pv.Visit_date, GETDATE()) BETWEEN 0 AND 730
              AND pv.doctor_id IN (48,160,190,221,238,282,295,297,301,302,
                                   334,339,348,351,384,385,393,394,406,408,412,416))
        OR
        /* ИЛИ была услуга ТМС 90-720 дней назад */
        EXISTS (SELECT 1 FROM patients_treatment pt
            WHERE pt.Patient_id = patients.patient_id
              AND pt.Procedure_id IN (1477, 21475, 23524)   /* ТМС */
              AND DATEDIFF(DAY, pt.Treatment_date, GETDATE()) BETWEEN 90 AND 720)
    )

    AND NOT EXISTS (SELECT 1 FROM messages m
         INNER JOIN deliv_orders do ON do.Order_id = m.Order_id
         WHERE do.Delivery_id = :DID
           AND m.Contact_info = patients.cellphone)
) vv
LEFT JOIN (
    SELECT v1.patient_id FROM patients v1
    INNER JOIN patients v2 ON v2.cellphone = v1.cellphone
    WHERE v1.patient_id > v2.patient_id
) duplicatePatients ON vv.patient_id = duplicatePatients.patient_id
WHERE
    duplicatePatients.patient_id IS NULL
    AND datepart(HOUR, GETDATE()) BETWEEN :ITIME1 AND :ITIME2
```

Для 4.3 анонс курса датирован («с 4 по 14 января») — если сценарий
одноразовый, ограничить ещё и `Stop_dt`/периодом в расписании.
