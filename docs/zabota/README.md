## Инструменты

- `tools/brief_group_match.py` — сверка услуг брифа (docx/txt) со справочником услуг
  и группами процедур: матчит названия с `procedures.Descr`, показывает нехватку
  и лишние услуги. `--find-only` — выдать `proc_id` по услугам брифа (для баз без групп).
- `tools/sql/recon/` — кит разведки незнакомой клиентской базы: карта таблиц,
  инвентарь объектов, поиск по именам/колонкам/коду, форма таблицы, активность,
  зависимости, сценарии рассылок. Порядок запуска — `tools/sql/recon/README.md`.
- `tools/schema_diff.py` — сравнение инвентаря клиентской базы с эталоном
  (`tools/sql/recon/reference/wellness_new_objects.txt`) → список кастома.
- `docs/zabota/clients/<Zabota_ID>/schema-map.md` — карта конкретной клиники
  (заводится по мере работы).
- `docs/zabota/clients/imed-city/birthday/` — 6 готовых SQL-сегментов сценариев
  поздравления с днём рождения для Imed City Clinic + разбор трактовок брифа.

## Доступ агента к рабочему ПК

- **Браузер пользователя** — MCP `browse` (плагин в Chrome). Работа со вкладками,
  чтение страниц, клики и ввод через `tools.browse.execute`. Так работаем с Битриксом.
- **Окна Windows** — MCP `windows`: `Snapshot` (дерево окон и элементов), `Screenshot`
  (снимок экрана, `display: [1]` — второй монитор с RDP), `Click`, `Type`, `Scroll`,
  `Shortcut`, `App` (запуск, переключение, размер окна), `PowerShell`.
- **Shell** — PowerShell из агента. Скрипт `tools/look_screen.ps1` иногда не может
  сохранить файл в `%LOCALAPPDATA%\Temp\opencode` (отказано в доступе), тогда
  пользоваться `Screenshot` из MCP `windows`.

Правила: сначала только просмотр (`Snapshot`, `Screenshot`). Клики, ввод текста и
закрытие окон — только по прямой просьбе пользователя. Не открывать файлы с паролями
(например, `пароли.txt`) и не выводить их содержимое в чат.
