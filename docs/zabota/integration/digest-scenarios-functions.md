# Дайджест: сценарии и SQL-функции

Выжимка по папкам `Desktop\интеграция\сценарии` и `Desktop\интеграция\Tariff`
(65 заметок `.md`/`.txt`). Пути — относительно `Desktop\интеграция`.
Полный SQL не копируется: смотри исходный файл.

Общие соглашения сценариев (встречаются почти везде):

- базовый фильтр `patients.exclude=0 and patients.hide=0` — «не исключён и есть контакт»;
- возраст `patients.age between :IAGE1 and :IAGE2`, пол `:IGEN` (1 — F, 2 — M, 0 — все);
- антидубль: `NOT EXISTS (messages m JOIN deliv_orders o ON o.Order_id=m.order_id WHERE o.Delivery_id=:DID AND DATEDIFF(DAY,o.created,GETDATE())<N)`;
- `:DID` — id сценария/доставки, `:IDAYS` — окно в днях, `:IVIS`/`:ISUM` — пороги количества/суммы.

## Сценарии

### 1.1 Сообщение о записи на прием (1 день — 1 сообщение)
- **Назначение:** подтверждение/информирование о записи на приём.
- **Таблицы/вью:** `VPatients_Recorded`, `patients_visits`, `messages`, `deliv_orders`.
- **Логика отбора:** `CROSS APPLY TOP 1` из `VPatients_Recorded ORDER BY Next_Visit_time` — берётся ближайшая будущая запись (одно сообщение на пациента, а не на каждую запись). Возраст в диапазоне; `:ISFIRST` (1 — первичный, 2 — повторный, 0 — все). Запись создана сегодня (`DATEDIFF(day, created, getdate())=0`) и визит на завтра и далее (`DATEDIFF(day,GETDATE(),visit_date)>0`). Нет сообщения этого `:DID` по этому `Appoint_id`.
- **Источник:** `сценарии/1.1Сообщение о записи на прием 1 день-1 сообщение.txt`

### Анкетирование «Сегодня и вчера»

- **Таблицы/вью:** `VPatients`, `dbo.ftGetPatientsVisitsInDaysRange`, `patients_visits`, `messages`, `deliv_orders`, `dbo.fsIsFirstVisit`.
- **Логика отбора:** визиты в окне `:IDAYS … :IDAYS+1` (при `:IDAYS=0` — сегодня/вчера); `fsIsFirstVisit(appoint_id,0)=1` — только первичный визит пациента; возраст и пол; визит был >45 минут назад и не отменён (`ISNULL(visit_state,'N')<>'C'`); не отправляли `:DID` 180 дней.
- **Источник:** `сценарии/Анкетирование Сегодня и вчера.txt`

### ВОРОНКА «Бешеная» (имплантация/протезирование после удаления)
- **Назначение:** воронка приглашения на имплантацию/протезирование после удаления зуба.
- **Таблицы/вью:** `vpatients`, `patients_treatment`, `patients_treatment_teeth`, `patients_visits`, `messages`, `deliv_orders`.
- **Логика отбора:** три ветки через `OR`, каждая = «было удаление/консультация» + «не получал протезирование/имплантацию» + «не было визитов к хирургу/ортопеду»:
  1. удаление не-8-го зуба ровно 50 дней назад (`tooth NOT IN (18,28,38,48)`), нет протетики 0–50 дней, нет визитов 0–49;
  2. удаление 0–90 дней назад + визит к хирургу/имплантологу ровно 10 дней назад, нет протетики 0–90, нет визитов ортопеда 0–89;
  3. консультация с планом имплантации/протезирования ровно 50 дней назад, нет протетики 0–50, нет визитов 0–49.
  Дополнительно: телефон `LIKE '79%'`, возраст 18–99, нет будущих записей 0–60 дней к списку врачей, нет `:DID` 180 дней.
- **Источник:** `сценарии/ВОРОНКА_Бешеная.txt`

## Функции и view

### dbo.fsIsFirst(@PatientID, @CustID)
- **Назначение:** «первичный пациент» (нет прошлых визитов и услуг).
- **Вход/выход:** `INT, INT → INT` (1/0). `@CustID=0` — любой филиал.
- **Нюансы:** 1, если нет ни одного неотменённого визита с датой в прошлом (`DATEDIFF(DAY,visit_date,GETDATE())>0`); затем принудительно 0, если есть любое лечение в прошлом. Визиты «сегодня» и будущие не учитываются.
- **Источник:** `Tariff/Функция скалярная dbo.fsIsFirst.txt`

### dbo.fsIsFirstVisit(@AppointID, @CustID)
- **Назначение:** первичность конкретного визита (для анкет/отзывов).
- **Вход/выход:** `INT, INT → INT` (1/0).
- **Нюансы:** сравнивает дату визита с датами других визитов пациента (`ov.Appoint_Id<>pv.Appoint_Id`, `DATEDIFF(DAY,ov.visit_date,pv.Visit_date)>0`) — то есть «на момент того визита». Если `Appoint_Id` не найден, `@First` остаётся `NULL`. Есть копия в `Tariff/функции/Функция скалярная dbo.fsIsFirstVisit.txt`; в «из инсталлера» версии потеряны операторы (`<>`, `>`) — файл битый, не использовать.
- **Источник:** `Tariff/Функция скалярная dbo.fsIsFirstVisit.txt`, `сценарии/Функция Скалярная ISFIRSTVISIT.txt`

### dbo.fsIsFirstVisitToDoctor(@Appoint_ID) (файл fsIsFirstToDoctors)
- **Назначение:** первичный ли визит к данному врачу.
- **Вход/выход:** `INT → INT` (1/0).
- **Нюансы:** 1 — у пациента не было визитов к тому же `Doctor_ID` ранее даты визита; иначе 0. Имя функции в файле (`fsIsFirstVisitToDoctor`) не совпадает с именем файла — при развёртывании согласовать. При отсутствии записи возвращает `NULL`.
- **Источник:** `Tariff/Функция скалярная dbo.fsIsFirstToDoctors.txt`

### dbo.fsIsFirstToDoctorsByGroup(@AppointID, @GroupID)
- **Назначение:** первичный ли визит к группе врачей (специальности).
- **Вход/выход:** `INT, INT → INT`: `-1` — запись не у врача этой группы (guard), `1` — первичный к группе, `0` — уже был.
- **Нюансы:** две версии расходятся: в `Tariff/Функция скалярная ...` условие `DATEDIFF(DAY, v1.Visit_date, getdate()) >= 0`, в `Tariff/функции/...` — `> 0`. При `-1` вызывающий код должен трактовать результат отдельно (сравнение `=1` в сценарии это учитывает).
- **Источник:** `Tariff/Функция скалярная dbo.fsIsFirstToDoctorsByGroup.txt`, `Tariff/функции/Функция скалярная dbo.fsIsFirstToDoctorsByGroup.txt`

### dbo.ftIsFirstToDoctorsByGroup(@AppointID) (файл tIsFirstToDoctorsByGroup)
- **Назначение:** табличный вариант «первичности к группе» с учётом групп с кодом `A%`.
- **Вход/выход:** `INT → TABLE(patient_id, Doctor_ID, Appoint_Id, group_id, isfirst)`.
- **Нюансы:** `group_id` подставляется только для групп с `doctorsgroups.code LIKE 'A%'` (при смене кодов — править); `isfirst=1`, если (группа найдена и нет прошлого визита к этому врачу) или (группы нет и у пациента вообще не было визитов). Внутри также считается `app0`.
- **Источник:** `Tariff/Функция табличная dbo.tIsFirstToDoctorsByGroup.txt`

### dbo.VisitsPerDay(@Patient_Id, @DAY)
- **Назначение:** текстовая сводка визитов пациента за день.
- **Вход/выход:** `INT, DATE → VARCHAR(500)` вида `др. Иванов И.И. в 10:30, ...`.
- **Нюансы:** собирается через `FOR XML PATH` + `STUFF`, отменённые визиты исключены; двойная обрезка строки (`STUFF` + `SUBSTRING(...,2,...)`) — хрупко при пустом результате.
- **Источник:** `Tariff/Функция скалярная dbo.VisitsPerDay.txt`

### dbo.ftSplitstring(@stringToSplit)
- **Назначение:** разбить строку по запятой.
- **Вход/выход:** `VARCHAR(MAX) → TABLE([Name] nvarchar(500))`.
- **Нюансы:** цикл `WHILE CHARINDEX(',')`; пробелы не тримятся; пустые элементы сохраняются; последний элемент добавляется после цикла (пустая строка → одна пустая строка).
- **Источник:** `Tariff/Функция табличная dbo.ftSplitstring.txt`

### dbo.ftGetPatientsLastVisitEx1(@Idayoff, @Idays)
- **Назначение:** последний неотменённый визит в заданном прошлом окне.
- **Вход/выход:** `INT, INT → TABLE(patient_id, doctor_id, visit_date, appoint_id)`. Пример: `(180,30)` — окно от 180 до 210 дней назад.
- **Нюансы:** окно задаётся `DATEDIFF(DAY, Visit_date, GETDATE()) BETWEEN @Idayoff AND @Idayoff+@Idays-1`; `TOP 1 ... ORDER BY visit_date` (по возрастанию) — фактически берётся **самый ранний** визит окна, а не последний; наличие будущих записей не проверяется. Полный дубль — `vPatients_LastVisitEx1`.
- **Источник:** `Tariff/Функция табличная dbo.ftGetPatientsLastVisitEx1.txt`

### dbo.vPatients_LastVisitEx1(@Idayoff, @Idays)
- **Назначение:** то же, что `ftGetPatientsLastVisitEx1`.
- **Вход/выход:** `INT, INT → TABLE(patient_id, doctor_id, visit_date, appoint_id)`.
- **Нюансы:** код идентичен; отдельное имя — историческое. Используется в «Сбор отзывов Анкетирование».
- **Источник:** `Tariff/функции/vPatients_LastVisitEx1.txt`

### dbo.vPatients_LastVisit1(@Idayoff, @Idays)
- **Назначение:** действительно последний визит окна — после него у пациента больше нет визитов.
- **Вход/выход:** `INT, INT → TABLE(patient_id, doctor_id, visit_date, appoint_id)`.
- **Нюансы:** добавлено `NOT EXISTS` более поздних неотменённых визитов (и в CTE, и в `CROSS APPLY`). **Две несовместимые версии:** в `Tariff/функции/vPatients_LastVisit1.txt` окно в прошлом (`DATEDIFF(DAY, Visit_date, GETDATE())`), а «из инсталлера» — в будущем (`DATEDIFF(DAY, GETDATE(), Visit_date)`), т.е. ищет будущие записи. Имя одно, поведение разное — проверять, какая версия стоит в БД. Третья копия (`CREATE FUNCTION dbo.vPatients_LastVIsit1.txt`) совпадает с прошлой-версией.
- **Источник:** `Tariff/функции/vPatients_LastVisit1.txt`, `Tariff/функции/vPatients_LastVisit1  из инсталлера.txt`

### dbo.vPatients_LastVisit(@Idayoff, @Idays)
- **Назначение:** визиты окна + статусы, только для «последних» пациентов.
- **Вход/выход:** `INT, INT → TABLE(Appoint_Id, Patient_Id, Doctor_ID, Visit_date, Visit_time, Visit_state, statuses)`.
- **Нюансы:** исключает пациентов, у которых был визит раньше `@Idayoff` (`DATEDIFF(DAY,v1.Visit_date,GETDATE()) < @Idayoff`), т.е. отбирает тех, для кого окно — действительно последняя активность. `statuses` — склейка токенов `visit_statuses` через `FOR XML PATH`.
- **Источник:** `Tariff/функции/vPatients_LastVisit.txt`

### dbo.vPatients_LastTreat1(@Idayoff, @Idays)
- **Назначение:** последняя услуга в окне и её врач.
- **Вход/выход:** `INT, INT → TABLE(Patient_Id, doctor_id)`.
- **Нюансы:** `TOP 1 ... ORDER BY treatment_date DESC` — берётся самая свежая услуга окна; отменённых услуг в модели нет.
- **Источник:** `Tariff/функции/vPatients_LastTreat1.txt`

- **Назначение:** записи, созданные сегодня, по филиалу — база для сообщений о записи.

### dbo.ftGetPatientsVisitsInDaysRange(@Start, @End)
- **Назначение:** визиты пациента в произвольном прошлом диапазоне (без «последнего»).

- **Нюансы:** `DATEDIFF(DAY, v.Visit_date, GETDATE()) BETWEEN @Start AND @End`; отменённые исключены; база — `vpatients`, поэтому фактически перебираются все пациенты (медленно на больших базах).

## Паттерны (переиспользуемые)

1. **Каркас сегмента:** `SELECT ... FROM vpatients WHERE exclude=0 AND hide=0 AND age BETWEEN :IAGE1 AND :IAGE2`.
2. **Антидубль по сценарию:** `NOT EXISTS (messages m JOIN deliv_orders o ... WHERE o.Delivery_id=:DID AND DATEDIFF(DAY,o.created,GETDATE())<N)`; вариант по контакту — `m.Contact_info=patients.cellphone`.
3. **Окно прошлых событий:** `DATEDIFF(DAY, event_date, GETDATE()) BETWEEN a AND b` (b=0 — включая сегодня).
4. **Отсечение будущих записей:** `DATEDIFF(DAY, GETDATE(), visit_date) BETWEEN 0 AND 60` (или `DATEDIFF(minute,...)>45/120`).
5. **«Запись создана сегодня»:** `DATEDIFF(DAY, created, GETDATE())=0` + условие на будущую дату визита.
6. **Сегмент по услугам:** `EXISTS/NOT EXISTS (patients_treatment WHERE Procedure_id IN (...) AND окно)` + `patients_treatment_teeth.tooth NOT IN (18,28,38,48)` для «не восьмёрок».
7. **Сегмент по врачам/специальностям:** список `Doctor_ID` или `doctorx.group_id`; группы специальностей — через `doctorsgroups.code LIKE 'A%'`.
8. **Лимит и темп рассылки:** `TOP N` + `datepart(HOUR,GETDATE()) BETWEEN ...`.
9. **Дедупликация:** `ROW_NUMBER() OVER (PARTITION BY cellphone ORDER BY patient_id DESC)=1` либо `NOT IN (... self-join по cellphone ...)`.
10. **Фильтр филиала:** `(cust_id=:ICUST OR :ICUST=0)`.
