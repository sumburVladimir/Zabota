# Дайджест: «всякие задачки»

Практическая выжимка из личных заметок по системе «Забота» (импорт МИС, сценарии рассылок, обслуживание БД).
Пути в поле «Источник» — относительно `C:\Users\Владимир Капов\Desktop\интеграция`.

## Сценарии: условия сегментов (SQL)

### Сообщение о записи на приём за 1 день (1 сообщение на визит)
- **Проблема:** пациенту уходит несколько сообщений о записи, нужно одно — по ближайшему визиту.
- **Решение:** `VPatients_Recorded` + `CROSS APPLY SELECT TOP 1 ... ORDER BY Next_Visit_time`; фильтры `exclude=0`, `hide=0`, возраст `:IAGE1..:IAGE2`, первичный/повторный `:ISFIRST`, запись создана сегодня и визит в будущем; защита от повтора через `NOT EXISTS` по `messages.Appoint_id` + `deliv_orders.Delivery_id=:DID`.
- **Таблицы/поля:** `patients`, `VPatients_Recorded`, `patients_visits` (`created`, `visit_date`), `messages`, `deliv_orders`.
- **Источник:** `1.1Сообщение о записи на прием 1 день-1 сообщение.txt`

### Напоминание по всем визитам дня, но только о первом визите к каждому доктору
- **Проблема:** при двух визитах к одному врачу в один день нужно напомнить только о первом.
- **Решение:** табличная функция `dbo.vPatients_NextVisit3(@Idays)` — берёт `TOP 1` неотменённый визит пациента к тому же `Doctor_ID` на нужный день, собирает токены статусов через `FOR XML PATH`.
- **Таблицы/поля:** `patients_visits` (`Visit_date`, `Visit_state<>'C'`), `visit_statuses.token`.
- **Источник:** `всякие задачки\!напоминалка по всем визитам в нужный день...txt`

### Выборка следующего визита по группе врачей
- **Проблема:** напоминания нужны только по определённой группе докторов.
- **Решение:** функция `dbo.vPatients_NextVisitDoc(@Idays,@idoc)`: первый неотменённый визит на день, фильтр по `doctorx.group_id` (`@idoc=0` — врачи без группы).
- **Таблицы/поля:** `patients_visits`, `doctorx` (`doctor_id`, `group_id`).
- **Источник:** `всякие задачки\Функция выборки следующего визита по группе докторов.txt`

### Реакция на ответ пациента по напоминанию
- **Проблема:** нужен сценарий, который срабатывает на ответ «Да / Перенести / Отменить».
- **Решение:** join `answers` к `VPatients`, фильтр `a.Req_type=1`, `a.Resp_code=:IRCOD` (1-Да, 2-Перенести, 4-Отменить), ответ получен сегодня, `NOT EXISTS` отправок за сегодня.
- **Таблицы/поля:** `answers` (`Received`, `Req_type`, `Resp_code`), `messages`, `deliv_orders`.
- **Источник:** `всякие задачки\Получение ответа на напоминание (1).txt`

### Отправка «впервые к врачу» (по группам врачей)
- **Проблема:** сценарий должен различать первичного и повторного именно к врачу/группе, а не к клинике.
- **Решение:** `dbo.fsIsFirstToDoctorsByGroup(appoint_id, 1)`; повторный к группе 1 **или** повторный к прочим (не входящим в группу 1); визит в будущем, `NOT EXISTS` по `Appoint_id`.
- **Таблицы/поля:** `VPatients_Recorded`, `vpatients.IsFirst`, `doctorx.group_id`, `messages`, `deliv_orders`.
- **Источник:** `всякие задачки\изменения для отправок первый раз к врачам.txt`

### Поздравление с ДР по филиалам
- **Проблема:** рассылка поздравлений только по конкретным филиалам и «активным» пациентам.
- **Решение:** ДР через `DAY/MONTH(Dob)` = дата +3 дня; возраст 18–65; телефон `79%`; сумма лечения > 200; был действительный визит за 0–364 дня; `cust_id IN (24,25)` (Дагестанская/Менделеева); нет отправок 180 дней.
- **Таблицы/поля:** `vpatients` (`Dob`, `age`, `cust_id`), `patients_treatment.Total`, `patients_visits`, `messages`, `deliv_orders`.
- **Источник:** `всякие задачки\Поздравление с ДР по филиалам.txt`

### Приглашение на гигиену во время ортодонтического лечения
- **Проблема:** нужно приглашать подростков на профгигиену при ортолечении, не дублируя записи и услуги.
- **Решение:** возраст 0–17; нет записи на чистку в 0–60 дней (`Doctor_ID IN (...)`); нет услуги снятия брекетов; была установка брекетов 90–1095 дней назад (наборы `Procedure_id`); не было гигиены 0–89 дней; нет сообщений 180 дней. В заметке есть спорные `OR`-ветки — проверять логику перед запуском.
- **Таблицы/поля:** `vpatients`, `patients_visits`, `patients_treatment` (`Procedure_id`, `Treatment_date`), `messages`, `deliv_orders`.
- **Источник:** `всякие задачки\приглашение на гигиену во время орт лечения.txt`

### Акция «с суммой» (amount) и отсев дублей
- **Проблема:** акция для «спящих» пациентов с крупными оплатами, без дублей по телефону.
- **Решение:** `TOP (:IPAT)`, телефон `79%`, исключение дублей по `cellphone` (оставляем минимальный `patient_id`), нет визитов на 0–60 дней к заданным врачам, был визит 61–1095 дней назад, сумма оплат > 10000, не было профгигиены 149 дней, нет отправок 180 дней, ограничение по часам; вложенный `vv`-подзапрос.
- **Таблицы/поля:** `vpatients`, `patients`, `patients_visits`, `patients_treatment` (`Total`, `Procedure_id`), `messages`, `deliv_orders`.
- **Источник:** `всякие задачки\акция с амоунтом.txt`

### Планы/курсы лечения: сценарий + кастомный импорт (Инфоклиника)
- **Проблема:** нужен сценарий по «курсу лечения» (массаж) и импорт планов лечения, которых нет в стандартной выгрузке.
- **Решение:** сценарий join `treatplan`/`treatplandet`, план 30 дней назад, `plan_type_id=10000011`, 2 услуги массажа за 16–30 дней, нет визитов 0–21 день, получено меньше `td.treat_count`, нет отправок 180 дней. Импорт: таблицы `treatplan(_tmp)`, `treatplandet(_tmp)`; выгрузка из `BI_TREATPLAN`/`BI_TREATPLANDET` (белая) и `DAILYPLAN`/`DAILYPLANDET` (серая), пагинация 500; в `spReplaceAll` добавить `TRUNCATE` + `INSERT ... SELECT` из `_tmp`.
- **Таблицы/поля:** `treatplan`, `treatplandet`, `patients_treatment`, `patients_visits`, `messages`, `deliv_orders`.
- **Источник:** `Планы-Курсы лечения кастом импорт в Инфоклинике+таблицы бд+сценарий интересный.txt` (дубль в `всякие задачки\`)

### Отправка по дням недели и времени
- **Проблема:** сценарий должен работать только в нужные дни/часы; нумерация дней различается.
- **Решение:** `DATEPART(WEEKDAY)` — в ПР2 ВС=1, СБ=7, в Word/вордже ПН=1, ВС=7; шаблоны `:IDAYW` (1 — ПН–ПТ, 2 — СБ, 0 — все), проверка `CONVERT(time,GETDATE())` в диапазоне; 1–7 проверять руками.
- **Таблицы/поля:** только `GETDATE()`.
- **Источник:** `отправка по дням недели (1).txt`

### Ограничение времени работы сценария
- **Проблема:** рассылка не должна уходить ночью/вне часов работы.
- **Решение:** `DATEPART(HOUR,GETDATE()) BETWEEN 9 AND 18`; точнее — `HOUR*60+MINUTE BETWEEN 660 AND 990` (11:00–16:30).
- **Таблицы/поля:** только `GETDATE()`.
- **Источник:** `всякие задачки\ограничить время работы сценария.txt`

### Исключение по тегу
- **Проблема:** не отправлять пациентам с определённым тегом (например, ДМС).
- **Решение:** `NOT EXISTS (SELECT 1 FROM patients_tags pt WHERE patients.patient_id=pt.patient_id AND pt.tag LIKE 'DMS')`.
- **Таблицы/поля:** `patients_tags` (`patient_id`, `tag`).
- **Источник:** `всякие задачки\исключать тег.txt`

## Исключения из отправок

### Исключение пациентов через БД (таблица patientx)
- **Проблема:** стандартное исключение пациента не работает, `xcard` у пациентов пустой.
- **Решение:** исключение хранится в `patientx` (`Card` вычисляется из `patient_id`); в `spReplaceAll` после заливки `patients` добавить `UPDATE patients SET xcard = patient_id;`.
- **Таблицы/поля:** `patients.xcard`, `patientx` (`Id`, `Card`, `patient_id`).
- **Источник:** `всякие задачки\исключение пациентов из отправок через БД.txt`, `как починить Не работающее ИКЛЮЧЕНИЕ пациентов.txt`

### PR2 исключает не по patient_id, а по xcard
- **Проблема:** в части версий PR2 (например, 2.20.1.6) исключение работает по `patient_id`, в других — по `xcard`, из-за чего исключения «не видны».
- **Решение:** выяснить режим (после исключения через «Пациенты» появляется запись в `patientx`); добавить `update patients set xcard = patient_id`; в `patientx` использовать `Card AS ([patient_id])`; таблицу создавать как `НАЗВАНИЕ_БД.dbo.patientx`; добавить extended property «Список исключенных из рассылок пациентов».
- **Таблицы/поля:** `patients.xcard`, `patientx`.
- **Источник:** `всякие задачки\если не работает исключение Pr2 .txt`

### Исключить врача из одного сценария
- **Проблема:** нужно убрать конкретного врача только из одного сценария.
- **Решение:** для напоминаний `v.doctor_id not in (...)`; для сообщений о записи `patients.doctor_id not in (...)`; отрицание списка через `NOT (patients.doctor_id in (...))`.
- **Таблицы/поля:** `patients.doctor_id`, представление с `v.doctor_id`.
- **Источник:** `всякие задачки\исключение доктора из отправок 1 сценария.txt`

### Исключить врача из всех отправок (правка spReplaceAll)
- **Проблема:** врач (например, технический/служебный) не должен попадать в визиты и услуги вообще.
- **Решение:** ID врача брать из `doctors_tmp`; в `dbo.spReplaceAll` при заливке `patients_visits`/`patients_treatment` добавить `doctor_id <> <ID>`; альтернатива — `doctors_ext.disabled=1` и `LEFT JOIN doctors_ext ... WHERE ISNULL(x.disabled,0)<>1`. Есть готовые версии процедуры «до/после» и инструкция.
- **Таблицы/поля:** `doctors_tmp`, `doctors_ext.disabled`, `patients_visits.doctor_id`, `patients_treatment.Doctor_ID`.
- **Источник:** `всякие задачки\исключить врача из всех отправок\` (`dbo.spReplaceALL.txt`, `вернуть обратно.txt`, `центр селютиной.txt`, `инстукция.txt`)

### Удалить кресло из отправок
- **Проблема:** визиты в конкретное кресло не должны попадать в рассылку.
- **Решение:** ID кресла взять из `In\out\chairs.csv`; в `In\scripts\visits.ns` в конец условия добавить `where id_armchairs <> <ID>;`.
- **Таблицы/поля:** `chairs.csv`, `visits.ns`, `id_armchairs`.
- **Источник:** `всякие задачки\удалить кресло из отправок.txt`

### В отправках нет ФИО
- **Проблема:** в сообщениях пустые ФИО пациента.
- **Решение:** скорее всего запущено два импорта одновременно — проверить и оставить один.
- **Таблицы/поля:** импорт, `patients`.
- **Источник:** `всякие задачки\если в отправках нет ФИО..txt`

### Нет ФИО доктора
- **Проблема:** импорт не заполняет ФИО врача.
- **Решение:** в ini-файле импортёра добавить `AutoSplitSurnameDisabled=1`.

## Отмены визитов

- **Проблема:** нужно массово помечать визиты отменёнными (`Visit_state='C'`) по статусам МИС или признаку.

### Визиты ошибочно считались отменёнными
- **Проблема:** из-за `>=` и неверной нумерации дней отменялись ещё не начавшиеся/поздние визиты.
- **Решение:** заменить `>=` на `>` и переписать дни: `Visit_time > '20:00' AND DATEPART(WEEKDAY,Visit_date) IN (0..5)`, `Visit_time > '18:00' AND ... IN (6,7)`.
- **Таблицы/поля:** `patients_visits.Visit_time`, `Visit_date`, `Visit_state`.
- **Источник:** `всякие задачки\визиты считались отмененными. Исправили.txt`

### «Починить отменённых» в D4W и не только

- **Решение:** в `in\status_types.csv` найти нужные буквы; добавить/обновить `config`: `ImportMode / IsCancelledStatus / value=D,L,N`; в процедуре `iscancelledstatus` раскомментировать блок D4W; выполнить импорт и только потом проверять.
- **Таблицы/поля:** `status_types.csv`, `config`, `visit_statuses`, `patients_visits`.

### spUpdateCancelledStatus: ограничить записи по времени (баг)

## Филиалы (cust_id)

### Разделение по филиалам в сценариях
- **Проблема:** один сценарий на несколько филиалов, нужен выбор филиала параметром.
- **Решение:** `((patients.cust_id=24 and :ICUST=1) OR (patients.cust_id=25 and :ICUST=2) OR (:ICUST=0))`; дополнительно `EXISTS` по `patients_visits` с тем же `Appoint_Id`, чтобы филиал совпадал с визитом.
- **Таблицы/поля:** `patients.cust_id`, `patients_visits.Appoint_Id/cust_id`.
- **Источник:** `всякие задачки\разделение по филиалам в сценариях sql.txt`

### Мультифилиальность: универсальное условие
- **Проблема:** разные типы сценариев используют разные алиасы таблиц.
- **Решение:** СОЗ/НАП по часам — `patients.cust_id = COALESCE(:CUST_ID, patients.cust_id)`; НАП по дням — `v.cust_id = COALESCE(:CUST_ID, v.cust_id)`; анкеты/НПС — `pl.cust_id = COALESCE(:CUST_ID, pl.cust_id)`; в выгрузку добавить `v.cust_id AS ClinicID` и `v.cust_id AS cust_id`.
- **Таблицы/поля:** `patients.cust_id`, `vpatients.cust_id`, анкеты.
- **Источник:** `интеграция.txt`

### Обновление филиала пациента по последнему визиту
- **Проблема:** `patients.cust_id` расходится с фактическим филиалом.
- **Решение:** `UPDATE p SET p.cust_id=v.cust_id FROM patients p CROSS APPLY (TOP 1 визит с Visit_state<>'C' и датой >= сегодня, ORDER BY Visit_date DESC)`; помечено «НЕ УДАЛЯТЬ».
- **Таблицы/поля:** `patients.cust_id`, `patients_visits` (`Visit_date`, `Visit_state`, `cust_id`).
- **Источник:** `всякие задачки\обновление филлиала по визиту.txt`

### Замена cust_id пациента по 3 критериям (fsGetCustomerId)
- **Проблема:** филиал пациента нужно определять по нескольким признакам, а не по последнему визиту.
- **Решение:** создать функцию `fsGetCustomerId`; в `spReplaceAll` после `insert into patients_visits` выполнить `UPDATE p SET p.cust_id = dbo.fsGetCustomerId(p.patient_id) FROM patients p`.
- **Таблицы/поля:** `patients.cust_id`, `patients_visits`.
- **Источник:** `всякие задачки\dbo_ftGetCustomerId(замена cust_id пациента по 3 критериям)\Инструкция (2).txt`

### Псевдонимы не работают (косяк с филиалами)
- **Проблема:** выгрузка 1С приходит с кодом филиала 7, но у пациентов все коды заменены на 1 → псевдонимы не привязываются.
- **Решение:** восстановить корректный `cust_id` пациентов из выгрузки/по визитам (см. скрипт обновления филиала), не «нормализовать» коды массово.
- **Таблицы/поля:** `patients.cust_id`, выгрузка 1С.
- **Источник:** `всякие задачки\Как починить псевдонимы пациентам (косяк с филиалами)\опис.txt`

## Импорт и интеграции

### Инфоклиника: ФИО приходит звёздочками
- **Проблема:** после обновления Инфоклиники изменилось хранение ФИО, в импорт попадают `***`.
- **Решение:** брать ФИО/телефон/ДР из представления `BIX_CLCONTACTS` (`x.firstname/lastname/midname/mobile_phone/bdate`), join по `pcode`; проверить, что число пациентов и контактов совпадает; `exclude` по `smsusetype`.
- **Таблицы/поля:** `BI_CLIENTS`, `BIX_CLCONTACTS`, `patients` (`firstname`, `surname`, `midname`, `cellphone`, `dob`).
- **Источник:** `ИНФОДЕНТ Если ФИО звездочками.txt`

### Импортёр ругается на неправильный диагноз или услугу
- **Проблема:** в выгрузке `NULL` в обязательных полях диагноза/услуги, импорт падает.
- **Решение:** в папке `in\scripts` в соответствующем скрипте добавить условие `IS NOT NULL` (пример для диагнозов: `SELECT ID as Diag_Id, Name, Text As descr FROM Diagnoses WHERE id IS NOT null`).

### Переход с WhatsApp на каскады
- **Проблема:** при переводе сценариев с прямого WA на каскадную отправку теряются тексты.
